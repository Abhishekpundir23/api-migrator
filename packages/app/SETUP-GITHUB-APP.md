# Setting up the GitHub App (production auth)

The migrator runs in two auth modes:

- **Pilot (default):** uses your `gh` CLI token. Great for demos and your own repos. **No setup needed.**
- **Production:** authenticates as a registered GitHub App installation. Required for customer repos — it's the scoped trust boundary customers expect.

Both modes run the *same* migration code. The only difference is how the token is obtained (see `packages/app/src/auth.ts`).

To enable production (App) mode, create a GitHub App and set three environment variables.

## 1. Create the App

Go to **https://github.com/settings/apps/new** (or your org's `/organizations/<org>/settings/apps/new`) and create a GitHub App with:

| Field | Value |
|---|---|
| GitHub App name | `api-migrator` (or your product name) |
| Homepage URL | your site |
| Webhook → Active | **Unchecked** (we don't use webhooks yet) |
| Repository permissions → **Contents** | **Read and write** (clone, commit, push) |
| Repository permissions → **Pull requests** | **Read and write** (open PRs) |
| Repository permissions → **Metadata** | Read-only (required, auto-included) |

> **Important:** Request the *minimum* scope. Contents + Pull requests + Metadata is all the migrator needs. Do **not** grant Administration or Workflows.

## 2. Generate a private key

After creating the app: **App settings → General → Private keys → Generate a private key**. A `.pem` file downloads — keep it secret.

## 3. Install the App

**Install App** on the account/org whose repos you want to migrate. Note the **installation ID** from the URL of the installed app page (`.../installations/<INSTALLATION_ID>`).

## 4. Set the environment variables

Copy `.env.example` to `.env` and fill in:

```bash
cp .env.example .env
```

```dotenv
# The App's numeric ID (App settings → General → "About" → App ID)
GH_APP_ID=123456

# The full contents of the .pem private key, including BEGIN/END lines.
# In a shell you can load it from the file:
GH_APP_PRIVATE_KEY=$(cat /path/to/your-app.private-key.pem)

# Optional: a fixed installation ID. If omitted, the migrator resolves the
# installation per-repo (slower, but supports many installations).
GH_APP_INSTALLATION_ID=42
```

## 5. Verify

```bash
node -e 'require("./packages/app/dist/auth.js").isAppMode() && console.log("App mode ✓") || console.log("gh fallback (pilot)")'
```

Once `GH_APP_ID` + `GH_APP_PRIVATE_KEY` are set, every migration runs as the App:
- Commits are authored by `<app-slug>[bot]`.
- PRs are opened by the App.
- The PR body footer reads "Generated by the api-migrator GitHub App."

## Notes

- **Permissions trust:** Apps request narrowly scoped repo access. Customers install the app and choose which repos to grant — you never get blanket access.
- **Per-repo installations:** If you support many customers, leave `GH_APP_INSTALLATION_ID` unset; `resolveAuth(slug)` looks up the installation for each repo.
- **Rotation:** Rotate the private key periodically (App settings → Private keys → Generate a new key, then delete the old one and update the env var).
